# Email

Outlayr queues every email and sends it through `@opencoredev/email-sdk`. `lib/emailSetup.ts` reads `EMAIL_PROVIDER` and the provider variables. `lib/sendEmail.ts` writes the message to `outboundEmails` and queues `mailDelivery.deliver` on a workpool, `noticePool` for policy notices and `emailPool` for the rest; `deliver` reads the row and sends it with `lib/deliverEmail.ts`. `log` never queues: it writes each message, code included, to the Convex logs.

## Traps

- **Not the `@opencoredev/convex-email` component.** Convex refuses `"use node"` inside components, in the CLI and on the backend, and that component sends SMTP from a Node action, so it cannot deploy. It also builds its client with telemetry on.
- **Every send is a Node action.** `deliver` sits in the `mailDelivery` group, a `GroupSpec.makeNode()`. The SDK core imports `node:fs`, `node:os` and `node:crypto` through its telemetry module, so only `lib/deliverEmail.ts` may import it; `lib/sendEmail.ts` runs in the auth HTTP action.
- **Codes sit in `outboundEmails`, never in workpool args.** The workpool only gets the row id, and `emailOutbox.settled` deletes the row however the send ends, so a code outlives its send by one mutation. A failure survives only in the logs. Policy notices get their own pool so a code never waits behind a notice run, and a code carries `expiresAt`: `deliver` drops it a minute before Better Auth would refuse it, so a backlog never sends a code too late to use.
- **Only transient failures retry.** `lib/deliverEmail.ts` copies the SDK's `retryable` flag onto `EmailError`: a dropped connection, a timeout, an SMTP 4xx reply, or HTTP 408, 409, 425, 429 and 5xx throw, and the workpool tries four times (1 s, 2 s, 4 s apart). Anything else (an SMTP 5xx reply, another HTTP 4xx, a rejected address, a missing setup) is `EmailError.permanent`: `deliver` returns its message, and `settled` counts it as failed without a retry.
- **A notice is claimed when queued and given back when it fails.** `enqueue` records the row's notice keys in the same transaction and queues only the keys no other run claimed, so overlapping `notifyPolicy` runs never email an account twice; `settled` removes the keys a failed row claimed, so the next run tries that account again.
- **Better Auth swallows send failures.** It catches errors thrown in its email callbacks and still answers 200 (or `EMAIL_NOT_VERIFIED` on password sign-in). So `createAuth` reads `emailProblem` once: while the setup is `unconfigured` or fails to parse, `hooks.before` refuses the paths that send a code with 503 and `sendOnSignIn` is off. A provider outage only shows in `outboundEmails` and the logs.
- **Node handlers need the Convex config provider.** Effect's default provider copies `process.env` once per process, and Confect only installs `ConvexConfigProvider` on the default runtime, so every `mailDelivery` handler provides `ConvexConfigProvider.layer` itself.
- **Telemetry is off by hand.** Every client passes `telemetry: false`. The SDK's telemetry is on by default and posts to the SDK author's PostHog.
- **A half-set provider never falls back to `log`.** With `EMAIL_PROVIDER` unset, any variable of a provider selects it, and an incomplete one is `unconfigured`. Otherwise removing one Cloudflare variable would quietly put codes in the logs.
- **Policy notices refuse `log`.** `notifyPolicy` fails with `unconfigured` on `log`, because a notice that only reached a log has reached nobody.
- **Provider failures hide their status.** The SDK wraps them in `EmailRouteError`, whose `failures` hold the `EmailAdapterError` with the HTTP `status`.
- **Adding a provider touches two files.** Extend `EmailProviderName`, `REQUIRED_VARIABLES`, `credentials`, `SENDING_ORDER` and the `setups` and `touched` records in `lib/emailSetup.ts`, add the adapter to `adapterFor` in `lib/deliverEmail.ts`, and pin the SDK exactly.
